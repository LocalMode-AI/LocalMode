# Summarization

Chrome AI provides on-device text summarization via the built-in Summarizer API. Your app ships and fetches no model files — Chrome supplies the model, downloading it once browser-wide on first use.

<Callout type="info" title="See it in action">
  The [Text Summarizer block](https://localmode.ai/blocks/writing-tools/summarize) runs Chrome AI summarization (with Transformers.js fallback) live in the browser.
</Callout>

## Basic Usage

```ts
import { summarize } from '@localmode/core';
import { chromeAI } from '@localmode/chrome-ai';

const { summary, usage } = await summarize({
  model: chromeAI.summarizer(),
  text: 'Long article text that needs summarizing...',
});

console.log(summary);
console.log(`Completed in ${usage.durationMs}ms`);
```

## Summary Types

Chrome AI supports four summary types:

```ts
// TL;DR — concise summary (default). Chrome's enum value is `tldr`, with no
// punctuation; passing 'tl;dr' throws a TypeError from the browser.
chromeAI.summarizer({ type: 'tldr' })

// Key Points — bullet-style key points
chromeAI.summarizer({ type: 'key-points' })

// Teaser — engaging preview
chromeAI.summarizer({ type: 'teaser' })

// Headline — single-line headline
chromeAI.summarizer({ type: 'headline' })
```

## Output Format

```ts
// Plain text (default)
chromeAI.summarizer({ format: 'plain-text' })

// Markdown
chromeAI.summarizer({ format: 'markdown' })
```

## Summary Length

```ts
chromeAI.summarizer({ length: 'short' })   // Brief
chromeAI.summarizer({ length: 'medium' })  // Balanced (default)
chromeAI.summarizer({ length: 'long' })    // Detailed
```

## Shared Context

Provide context that applies to all summarizations in a session:

```ts
const medicalSummarizer = chromeAI.summarizer({
  type: 'key-points',
  sharedContext: 'These are medical research papers. Focus on methodology and findings.',
});

const { summary } = await summarize({
  model: medicalSummarizer,
  text: researchPaper,
});
```

## Languages

Set the summary language and the expected input and context languages. Chrome logs a console
warning when `outputLanguage` is missing; all three are unset by default.

```ts
chromeAI.summarizer({
  outputLanguage: 'en',            // en, es, ja, de, fr
  expectedInputLanguages: ['en', 'de'],
  expectedContextLanguages: ['en'],
});
```

They go to `availability()` and `create()` only when set, can be overridden per call through
`providerOptions.chromeAI` (which recreates the session), and appear in `getModelInfo()`.

## Model Availability & Download

The Summarizer API can be present while its on-device model is not yet downloaded. Ask Chrome first:

```ts
// 'available' | 'downloadable' | 'downloading' | 'unavailable'
const state = await Summarizer.availability({ type: 'tldr', length: 'medium' });
```

When the state is `downloadable` or `downloading`, `chromeAI.summarizer()` throws a
`SummarizationError` rather than silently starting a large, browser-wide download. Opt in
explicitly, and call it from a **user activation** (a click) — Chrome refuses to start the
download otherwise:

```ts
import { summarize } from '@localmode/core';
import { chromeAI } from '@localmode/chrome-ai';

const model = chromeAI.summarizer({
  type: 'tldr',
  allowDownload: true,
  onProgress: ({ loaded, total }) => {
    console.log(`Downloading model: ${Math.round((loaded / total) * 100)}%`);
  },
});

// Call this from a click handler.
const { summary } = await summarize({ model, text: article });
```

<Callout type="info">
  Building this UI? `useProviderFallback` from `@localmode/react` exposes `chromeAvailability`
  and `requestChromeDownload`, and the `ui/local-first/chrome-ai-download-gate` primitive renders
  the button, progress, and terminal states for you.
</Callout>

## Errors

`ChromeAISummarizer` throws a typed `SummarizationError` from `@localmode/core`:

| Situation | Hint |
| --- | --- |
| `self.Summarizer` is undefined | Requires Chrome 138+ stable on desktop |
| `availability()` reports `unavailable` | This device or Chrome build cannot run the model |
| Model not downloaded and `allowDownload` unset | Set `allowDownload: true` and call from a user activation |
| `summarizeStreaming()` / `measureInputUsage()` missing (`code: 'chrome-ai-streaming-not-supported'` / `'chrome-ai-measure-not-supported'`, `retryable: false`) | Use `doSummarize()` / a character budget |
| Stream failed (`code: 'chrome-ai-summarization-failed'`, Chrome's error as `cause`) | Check the input against the quota |

## Streaming

`doStreamSummarize()` streams one summary through Chrome's `summarizeStreaming()`. Each
chunk arrives as Chrome sent it, stamped with `performance.now()`; the last item carries the
timing and usage.

```ts
const model = chromeAI.summarizer({ type: 'tldr', length: 'short' });

for await (const chunk of model.doStreamSummarize({ text: article })) {
  if (!chunk.done) {
    output.textContent += chunk.text;
  } else {
    const { requestedAt, firstChunkAt, endedAt } = chunk.timing!;
    console.log(`first chunk ${firstChunkAt! - requestedAt} ms, total ${endedAt - requestedAt} ms`);
  }
}
```

Options: `text`, `context` (per call), `maxLength`, `abortSignal`, `providerOptions`. `requestedAt`
is taken after the session exists, so the timings exclude session creation and any download.
An abort surfaces as an `AbortError`.

## Input Quota

```ts
const quota = await model.getInputQuota();           // number, or null if not exposed
const usage = await model.measureInputUsage(article); // Chrome's own count
if (quota !== null && usage > quota) { /* shorten the input */ }
```

## Model Info

`getModelInfo()` records what the page can see: the `availability()` state before `create()`
(`'timeout'` if it never answered), the options passed to `create()` and as the session reports
them, `inputQuota`, and the Chrome build (`brands`, `fullVersionList`) from
`getChromeBuildInfo()`.

```ts
const info = await model.getModelInfo();
// { api: 'Summarizer', availabilityAtCreate: 'available', sessionOptions: { type: 'tldr', ... },
//   inputQuota: 9216, modelVersion: null, browser: { fullVersionList: [...] , ... } }
```

<Callout type="warn">
  Chrome does not expose the on-device model version to web pages, so `modelVersion` is always
  `null`. Read it from `chrome://components` (Optimization Guide On Device Model) outside the page.
</Callout>

## With AbortSignal

```ts
const controller = new AbortController();

const { summary } = await summarize({
  model: chromeAI.summarizer(),
  text: longArticle,
  abortSignal: controller.signal,
});

// Cancel if needed
controller.abort();
```
